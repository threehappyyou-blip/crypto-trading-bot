# Crypto Trading Bot (Paper Trading MVP)

클로드(Claude)를 판단 엔진으로 쓰는 암호화폐 스윙 트레이딩 봇입니다.
**실제 돈은 전혀 움직이지 않습니다** — 업비트의 실시간 공개 시세를 그대로 받아와서,
"만약 진짜 주문을 넣었다면 어떻게 됐을지"를 가상 자본으로 시뮬레이션합니다.

## 왜 이렇게 만들었는가

- 가격 데이터는 100% 진짜(업비트 실시간 공개 API), 돈만 가상 — 그래서 나오는 수익률/손익 데이터가
  실제 시장 상황을 반영한 진짜 데이터입니다. warminsight 콘텐츠에 그대로 쓸 수 있습니다.
- 업비트 공개(시세) API는 인증 없이 접근 가능해서, 계좌 개설이나 KYC 없이 바로 시작할 수 있습니다.
- 매 캔들마다 클로드를 호출하지 않고, 지표 이벤트(EMA 크로스, RSI 임계값 이탈)가 발생했을 때만
  호출해서 API 비용을 통제합니다.
- 클로드의 판단과 무관하게 코드 레벨에서 하드스탑/서킷브레이커를 강제합니다 — AI 판단 실수에
  대비한 안전장치입니다.

## 구조

```
config.py            모든 설정값 (코인 유니버스, 가상자본, 리스크 파라미터)
upbit_data.py         업비트 공개 API에서 캔들 데이터 수집 (실시간 + 과거 페이지네이션)
indicators.py         EMA / RSI / ATR / 거래량 급증 계산
trigger.py            이벤트(신호) 감지 — 이때만 클로드 호출
claude_judge.py        클로드에게 판단 요청 (프롬프트 템플릿 + JSON 파싱/검증)
portfolio_sim.py       가상 포트폴리오 (체결, R-멀티플, 하드스탑, 서킷브레이커, 상태 저장/로드)
logger.py              판단 근거·체결·자산 스냅샷을 CSV로 누적 기록
main.py                위 전체를 한 번 실행하는 오케스트레이터 (스케줄 실행 전제)
backtest.py            과거 데이터를 한 번에 리플레이해서 전략을 빠르게 사전 검증
generate_report.py     매매 기록을 종목별 승률/R-멀티플 히트맵(PNG)으로 시각화
tests/test_logic.py    합성 데이터로 로직 검증 (업비트 API 접근 없이도 실행 가능)
```

## 빠른 사전 검증: 백테스트 + 히트맵 리포트

90일을 실시간으로 기다리기 전에, 과거 데이터로 전략을 먼저 훑어볼 수 있습니다.

```bash
python backtest.py --days 90          # 최근 90일 리플레이 (config.COIN_UNIVERSE 전체)
python generate_report.py --trades logs/backtest_trades.csv --out logs/backtest_heatmap.png
```

`backtest.py`는 `main.py`와 완전히 같은 지표·트리거·클로드 판단·리스크 관리 코드를
그대로 재사용해서 과거 캔들을 순서대로 리플레이합니다. 라이브 페이퍼 트레이딩
로그(`logs/portfolio_state.json` 등)와는 분리된 별도 파일(`logs/backtest_*`)에
기록되므로 `main.py` 운영에 영향을 주지 않습니다.

다만 트리거가 뜰 때마다 실제 Anthropic API를 호출하므로(과거 데이터라고 가짜 응답을
쓰지 않습니다), 기간을 너무 길게 잡으면 API 비용이 늘어납니다. 그리고 완벽한
미래참조 방지를 보장하지는 않으므로, 백테스트 성과만 보고 "검증 완료"로 콘텐츠에
공개하지 마세요 — 사전 감각을 잡는 용도이고, 최종 신뢰는 반드시 실시간 페이퍼
트레이딩 결과로 확인해야 합니다.

`generate_report.py`는 `trades.csv`(또는 백테스트 결과)를 종목별로 집계해 콘솔 표와
PNG 히트맵을 만듭니다. 각 셀에는 R-멀티플(진입 시 감수한 리스크 대비 몇 배를
벌었는지/잃었는지), 승률, 매매 건수가 함께 표시되고, 색은 파랑(이익)/주황(손실)
다이버징 팔레트를 씁니다(적록색맹 사용자도 구분 가능하도록 빨강/초록 대신 선택했고,
어차피 모든 셀에 실제 수치를 텍스트로 함께 표기해 색에만 의존하지 않습니다). 이
이미지는 warminsight/thegeolog 콘텐츠에 바로 써도 되는 형태로 만들었습니다.

한글이 이미지에서 네모(□)로 깨져 보이면 한글 지원 폰트가 없는 환경입니다. Linux는
`sudo apt install fonts-noto-cjk`로 해결되고(GitHub Actions 워크플로우에는 이미
반영해뒀습니다), Mac/Windows는 보통 기본 폰트에 한글이 포함돼 있어 문제 없습니다.

## 빠르게 시작하기

```bash
pip install -r requirements.txt
cp .env.example .env   # .env에 ANTHROPIC_API_KEY 채워넣기
python tests/test_logic.py   # 로직이 정상 동작하는지 먼저 확인 (네트워크 불필요)
python main.py                # 실제 1회 실행 (업비트 API + 클로드 API 호출)
```

`main.py`를 실행할 때마다 `logs/` 폴더에 아래 파일들이 쌓입니다.

- `decisions.csv` — 트리거가 뜰 때마다 클로드가 내린 판단과 근거(reasoning)
- `trades.csv` — 실제로 체결(가상)된 매매 기록 (손익 포함)
- `equity_curve.csv` — 실행할 때마다의 총자산 스냅샷 (수익률 곡선용)
- `portfolio_state.json` — 다음 실행에 이어서 쓸 포트폴리오 상태 (자동 관리, 직접 편집 X)

## 상시 실행: GitHub Actions로 돌리기

`.github/workflows/run_bot.yml`이 이미 포함되어 있습니다. warminsight에서 쓰시는 것과 동일한
GitHub Actions cron 패턴입니다.

1. 이 폴더를 GitHub 레포로 push
2. 레포 Settings → Secrets and variables → Actions에 `ANTHROPIC_API_KEY` 등록
3. 기본 설정은 매시 정각 실행. 필요하면 `run_bot.yml`의 `cron` 값을 조정
4. 실행 결과(`logs/`)는 워크플로우가 자동으로 다시 커밋해서 실행 간 상태를 유지합니다

회사 업무 중에도 신경 쓸 필요 없이 자동으로 돌아갑니다.

## 검증 기간 & 다음 단계

- 최소 60~90일, 또는 매매 30건 중 먼저 도달하는 시점까지는 "검증 중"으로 간주하고
  warminsight에는 짧은 진행 상황만 공유하는 걸 권장합니다.
- 검증 종료 후 `logs/trades.csv`, `logs/equity_curve.csv`, `logs/decisions.csv`를 바탕으로
  첫 "숫자 공개" 글을 작성하시면 됩니다 (수익률, 승률, R-멀티플, 최대낙폭(MDD), 매매 건수,
  예상과 달랐던 판단 사례를 reasoning에서 그대로 인용). `generate_report.py`로 만든 히트맵
  이미지를 함께 넣으면 시각적으로도 바로 쓸 수 있습니다.
- **콘텐츠에 넣을 때 반드시 포함할 디스클레이머**: "개인 실험 기록이며 투자 조언이 아닙니다.
  저는 금융 전문 자격이 없습니다. 실시간 시세 기반 모의투자 결과이며, 실제 체결과는 슬리피지 등으로
  미세한 차이가 있을 수 있습니다. 과거 성과가 미래 수익을 보장하지 않습니다."

## 코인 유니버스 / 자본 / 리스크 파라미터 바꾸기

전부 `config.py` 상단에 있습니다. 예: 종목 추가, 가상 자본 규모, 포지션당 최대 비중,

## 거래량 단독 트리거 (선택 기능)

"가격이 바닥이든 고점이든 거래량이 급증한 종목을 주목해야 한다 — 실적 개선/턴어라운드
뉴스가 나올 때 세력이 매집하며 거래량이 먼저 터지는 경우가 많다"는 통념을 반영한
옵션입니다. 기본적으로 트리거는 EMA 크로스나 RSI 임계값 이탈이 있을 때만 발생하는데,
`config.py`의 `ENABLE_STANDALONE_VOLUME_TRIGGER`를 `True`로 바꾸면 그런 기술적 신호가
없어도 거래량만 급증하면 클로드에게 판단을 요청합니다.

다만 이 봇은 뉴스나 공시 데이터를 받아오지 않으므로, 거래량이 왜 튀었는지는 클로드도
알 수 없습니다 — 그래서 `claude_judge.py`의 프롬프트에 "원인을 모른다는 걸 인정하고,
가격/지표가 방향성을 뒷받침하지 않으면 hold하라"는 규칙을 명시해뒀습니다. 이 옵션을
켜면 트리거 빈도(=클로드 API 호출 횟수=비용)가 늘어나니, 켜기 전에 그 점을 고려하세요.

## 익절(테이크프로핏) / 손익비(RR) 옵션

"승률보다 손익비(risk-reward ratio)가 더 중요하다"는 콘텐츠를 보고 추가한 옵션입니다.
손익비의 수학 자체는 사실입니다 — 손익비가 1:R이면, 손해를 안 보고 본전(breakeven)만
치려고 해도 필요한 승률은 `1 / (1 + R)`입니다. 예를 들어 1:2면 승률 33.3%만 넘어도
장기적으로는 이익이라는 뜻입니다. 다만 영상에서 나온 "승률 30%만 돼도 계속 번다"는
결론은 그 30%라는 승률이 실제로 이 봇의 전략(EMA/RSI/거래량 트리거 + 클로드 판단)에서
나온다는 보장이 있어야 성립합니다 — 손익비를 크게 잡을수록 목표가까지 도달하는 빈도
자체가 줄어드는 트레이드오프가 있어서, "손익비만 키우면 무조건 이득"은 아닙니다.
그래서 주장을 그대로 믿고 적용하는 대신, 코드로 만들어서 `backtest.py`로 직접
숫자를 확인할 수 있게 했습니다.

**동작 방식**: `config.ENABLE_TAKE_PROFIT = True`(기본값)이면, 매수 진입 시점에
"리스크"(진입가 - 손절가)를 계산해 그 `config.TAKE_PROFIT_RR_MULTIPLE`배 위에
익절가를 설정합니다. 기본값은 `2.0`(손익비 1:2)입니다. 가격이 그 익절가에 도달하면
클로드 판단을 기다리지 않고 하드스탑과 동일하게 코드 레벨에서 즉시 청산합니다
(`reason: "take_profit"`으로 `trades.csv`에 기록됩니다). `False`로 끄면 기존처럼
클로드의 "sell" 판단에만 의존해서 청산합니다(익절가 자체가 설정되지 않음).

**직접 검증하는 방법**: 옵션을 켠 상태/끈 상태, 또는 배수(1.5 / 2.0 / 3.0 등)를
바꿔가며 같은 기간으로 백테스트를 돌려서 결과를 비교하시면 됩니다.

```bash
python backtest.py --days 90 --reset                # config.py 현재 설정대로 실행
python generate_report.py --trades logs/backtest_trades.csv --out logs/backtest_tp_on.png

# config.py에서 ENABLE_TAKE_PROFIT = False 로 바꾼 뒤
python backtest.py --days 90 --reset
python generate_report.py --trades logs/backtest_trades.csv --out logs/backtest_tp_off.png
```

두 히트맵의 승률/R-멀티플/매매 건수를 비교하면, 이 봇의 실제 트리거 조건에서
손익비 옵션이 도움이 되는지 아닌지를 숫자로 확인할 수 있습니다. 결론이 나기 전까지는
"손익비 전략을 쓴다"고 콘텐츠에 단정하지 말고, "테스트 중"으로 표현하시길 권합니다.

## 콘텐츠 초안 자동 생성 (5건마다)

CSV 로그만 쌓이면 로인님이 직접 파일을 열어보지 않는 한 무슨 일이 있었는지 알 수가
없습니다. 그래서 청산된 매매가 5건씩 쌓일 때마다(`content_digest.py`,
`config`가 아니라 `content_digest.DIGEST_MILESTONE` 값으로 조정 가능), 그 구간의
승률·손익·R-멀티플과 클로드의 실제 판단 근거를 모아 클로드에게 블로그용 짧은
한국어 초안을 요청하고 `logs/content_drafts/digest_NNN.md`로 저장합니다.

- `main.py` 실행 끝에서 자동으로 체크됩니다 — 따로 실행할 필요 없습니다.
- GitHub Actions가 `logs/` 전체를 커밋하므로, 이 초안 파일도 자동으로 레포에
  올라갑니다. warminsight/thegeolog 글을 쓰실 때 이 폴더만 확인하시면 됩니다.
- 초안은 그대로 발행하지 말고 반드시 검토 후 다듬어서 쓰세요 — 숫자는 있는 그대로
  인용하도록 프롬프트에 명시해뒀지만(좋게 포장 금지), 문장 톤은 로인님 스타일로
  손보시는 걸 권합니다.
- 다이제스트 생성이 실패해도(API 오류 등) 봇의 매매 자체에는 전혀 영향을 주지
  않습니다 — `claude_judge.py`와 같은 안전 원칙입니다.
- 지금은 몇 건이 쌓였는지 로인님이 레포를 직접 들어가서 확인해야 합니다. 매번
  들어가 확인하기 번거로우시면, 새 초안이 올라올 때 알림을 받는 방법도 있으니
  필요하시면 말씀해주세요.

## 주의사항 (반드시 읽어주세요)

- 이 코드는 이 세션(샌드박스)에서 외부 네트워크 정책상 업비트 API에 실제로 접근하지 못해,
  로직은 합성(가짜) 데이터로만 검증했습니다 (`tests/test_logic.py`, 5개 테스트 모두 통과).
  실제 업비트 응답 형식과 완전히 일치하는지는 로인님 환경에서 `python main.py`를 한 번
  실행해보시면서 확인이 필요합니다.
- 이후 실거래(라이브)로 전환하려면 별도로 업비트 실명계좌/API 키 발급, 주문 실행 코드 추가가
  필요합니다. 이 MVP는 페이퍼 트레이딩 전용입니다.
- 이 프로젝트는 투자 조언 도구가 아니라 개인 실험/콘텐츠 제작용 도구입니다.
